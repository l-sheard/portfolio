A month into my first graduate role, a few things have surprised me enough to write down.

## The codebase doesn't care about your grade

University rewards getting to a working answer. Production code rewards code that's still understandable in two years, by someone who isn't you. Those are genuinely different skills, and nobody really tells you that until you're staring at a pull request review asking "why not just extract this into a hook?"

## Reading code is the job, more than writing it

I expected to spend most of my time writing new features. In practice I spend far more time reading existing code — understanding why something was built a certain way before I touch it. Getting comfortable moving through a large, unfamiliar codebase turned out to be a bigger unlock than any specific language feature.

## Asking questions early saves everyone time

My biggest early mistake was sitting on a blocker for half a day instead of asking a quick question in Slack. Every senior engineer I've worked with has said the same thing: they'd rather answer five small questions than review a pull request built on a wrong assumption.

## What's next

I'm planning to write more of these as I go — partly for anyone else making the same jump, partly so I can look back at the start of the year and see what's changed.
